# Game Documentation

## Principle

Document the current playable truth and the decisions needed to change it. Keep documentation small enough to maintain.

## Minimum Set

Maintain a concept, core loop, prototype scope, controls, architecture map, asset register, test notes, cut list, and next increment. Add player, developer, operations, commerce, online-service, or API guidance only when the project needs those audiences.

## Practice

Name owners and freshness. Link claims to builds, code, research, or decisions. Separate shipped behavior, planned behavior, assumptions, and open questions. Update the authored source rather than generated output.
