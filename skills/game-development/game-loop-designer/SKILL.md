# Game Loop Designer

## Purpose

Make the repeated play cycle understandable, buildable, and testable.

## When to Use

Use after concept framing or when play feels aimless, slow, or unrewarding.

## Inputs

Player goal, actions, rules, feedback, progression idea, session length, prototype, and playtest evidence.

## Process

1. Map player action → state change → feedback → next choice.
2. Define entry, success, failure, recovery, and ending.
3. State what repetition develops: mastery, discovery, tension, expression, or progress.
4. Remove steps that delay meaningful action.
5. Specify one instrumented or observable playtest.
6. Record tuning assumptions, cuts, owner, and next playable increment.

## Outputs

Loop diagram, timing assumptions, feedback map, failure/recovery behavior, and validation plan.

## Quality Bar

A player can enter and repeat the loop without coaching, and each step has a visible implementation owner.
