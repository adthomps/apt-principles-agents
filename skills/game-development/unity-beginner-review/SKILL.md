# Unity Beginner Review

## Purpose

Evaluate Unity against a project’s learning, prototype, asset, deployment, and maintenance needs.

## When to Use

Use when Unity is shortlisted or a beginner needs a review of a Unity project plan.

## Inputs

Game concept, 2D/3D needs, targets, C# comfort, scenes, assets, deadline, budget constraints, and current [Unity documentation](https://docs.unity3d.com/).

## Process

1. Verify current editor, package, license, build, and target requirements officially.
2. Map the prototype to scenes, GameObjects/components, scripts, input, data, and saves.
3. Build or inspect one complete loop with placeholder assets.
4. Check assembly/project organization, state ownership, references, and reset behavior.
5. Identify packages, services, and polish to defer.
6. Record evidence, owner, tests, rollout, rollback, and support needs.

## Outputs

Fit assessment, beginner project map, learning gaps, prototype tasks, risks, and cut list.

## Quality Bar

Material claims are current and sourced; the proposed structure remains smaller than the prototype problem.
