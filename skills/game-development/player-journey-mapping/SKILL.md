# Player Journey Mapping

## Purpose

Align mechanics and interfaces with the player’s changing knowledge and experience.

## When to Use

Use for onboarding, tutorials, difficulty progression, retention questions, or confusing playtest results.

## Inputs

Player profile, desired experience, session flow, mechanics, UI, accessibility needs, and observed evidence.

## Process

1. Map arrival, first action, learning, challenge, recovery, mastery, and ending.
2. Record what the player sees, believes, does, and receives at each stage.
3. Mark unanswered questions, emotional peaks, friction, and accessibility barriers.
4. Link each problem to evidence rather than preference.
5. Prioritize changes that unblock the core loop.
6. Record owner, validation, cuts, support, and documentation effects.

## Outputs

Player journey, evidence gaps, prioritized changes, test questions, and cut list.

## Quality Bar

The map distinguishes observed behavior from assumptions and produces testable changes.
