# Phaser Beginner Review

## Purpose

Evaluate Phaser for a small web-first 2D game and make its project flow understandable.

## When to Use

Use when a browser-delivered 2D prototype and JavaScript or TypeScript workflow are likely fits.

## Inputs

Concept, target browsers, coding comfort, scene flow, assets, input needs, hosting, deadline, and current [Phaser documentation](https://docs.phaser.io/).

## Process

1. Verify current setup, browser, renderer, input, asset, and deployment requirements.
2. Map the prototype to scenes, state, game objects, input, physics needs, UI, and saves.
3. Build or inspect one complete loop.
4. Check resize, focus, touch, loading, cleanup, and state transitions.
5. Defer plugins and abstractions not required by evidence.
6. Record owner, tests, rollout, rollback, documentation, and cuts.

## Outputs

Fit assessment, scene/project map, browser risks, learning steps, and prototype plan.

## Quality Bar

The recommendation is demonstrated on target browsers and keeps DOM/UI integration explicit.
