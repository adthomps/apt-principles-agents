# Game Scope Review

## Purpose

Protect a finishable prototype by exposing hidden content, asset, code, test, and support work.

## When to Use

Use before implementation, at milestone review, or whenever features grow faster than playable evidence.

## Inputs

Concept, loop, feature list, constraints, roadmap, assets, target platforms, current build, and owner.

## Process

1. State the prototype question and non-negotiable player promise.
2. Inventory mechanics, scenes, content, assets, platforms, and dependencies.
3. Classify each item as must prove, useful next, or not now.
4. Replace systems with one authored case or placeholder where possible.
5. Identify the smallest end-to-end playable path.
6. Produce cuts, owner, validation date, rollout, rollback, and next increment.

## Outputs

Scope decision, minimum playable prototype, dependency risks, explicit cut list, and review status.

## Quality Bar

Every retained item supports the core loop; every cut is concrete; the prototype has an observable ending.
