# Godot Beginner Review

## Purpose

Evaluate Godot against a project’s learning, prototype, asset, export, and maintenance needs.

## When to Use

Use when Godot is shortlisted or a beginner needs a review of a Godot project plan.

## Inputs

Game concept, 2D/3D needs, targets, coding comfort, scene plan, assets, prototype deadline, and current [Godot documentation](https://docs.godotengine.org/).

## Process

1. Verify current editor, language, export, and target-platform requirements officially.
2. Map the prototype to scenes, nodes, scripts, resources, input actions, and saved data.
3. Build or inspect one complete loop with placeholder assets.
4. Check project organization, signals/coupling, state ownership, and reset behavior.
5. Identify learning steps and features to defer.
6. Record evidence, owner, tests, rollout, rollback, and support needs.

## Outputs

Fit assessment, beginner project map, learning gaps, prototype tasks, risks, and cut list.

## Quality Bar

Advice matches the current project and official documentation rather than generic engine enthusiasm.
