## Architecture

Human-authored canonical doctrine and reusable assets feed manifests, validators, installers, and tool-specific adapter surfaces; generated catalogs and archives remain non-authoritative projections or historical evidence.

- Principles and standards define canonical judgment and required practice.
- Structured taxonomy and publication contracts define how canonical guidance is classified and which reviewed artifacts may appear on public surfaces.
- Skills, agents, prompts, templates, examples, checklists, context, and routing provide reusable operational capabilities.
- Manifests select installable bundles while installers and scripts validate, distribute, scan, synchronize, and repair managed assets.
- Platform directories adapt canonical assets for Codex, Claude, Gemini, GitHub Copilot, VS Code, and local-model consumers.
- Documentation, references, product hubs, and knowledge assets support adoption, contracts, and retrieval without replacing canonical sources.

- Runtime model: On-demand Node.js command-line scripts and PowerShell/Bash wrappers; no resident process, API server, database, or local web server.
- Deployment model: Assets are installed or synchronized into independent target repositories through manifests and lifecycle commands. The repository itself has no production deployment target.
