# Game Development Glossary

- **Game loop:** the repeated cycle of player action, game response, feedback, and another choice.
- **Mechanic:** a rule that turns an action or condition into a change in the game.
- **Scene:** a container for a place, screen, level, or runtime state, depending on the engine.
- **Entity:** a distinct game thing such as a player, enemy, item, or trigger.
- **Component:** a focused piece of data or behavior attached to or composed into a game thing.
- **Sprite:** a 2D image used to display a character, object, effect, or interface element.
- **Collision:** detection that shapes or objects touch, overlap, or cross.
- **Physics:** simulation of movement and forces; many games use simplified rules rather than physical realism.
- **State:** current information the game needs, such as score, position, inventory, or whether a door is open.
- **Save data:** selected state and settings stored so they can survive closing the game.
- **Level:** an arranged section of play that presents goals, learning, challenges, and an ending or transition.
- **Playtest:** observing people play to answer questions about understanding, experience, balance, or usability.
- **Prototype:** a small experiment built to answer an uncertain design or technical question.
- **Vertical slice:** a narrow portion of the game built near intended production quality to demonstrate how finished systems fit together.
- **HUD:** the heads-up display showing information needed during play, such as health, score, or objectives.
- **Asset:** a file used by the game, such as art, audio, animation, font, model, or data.
- **Build:** a runnable packaged version of the game.
- **Frame:** one visual update; game rules should not accidentally run faster only because more frames are rendered.

Definitions vary across engines. Use the project’s own glossary when a term has a more specific meaning.
